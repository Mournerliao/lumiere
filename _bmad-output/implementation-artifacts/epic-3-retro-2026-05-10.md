## What Went Well

- **Release-to-capture flow** — The core MVP interaction (drag + release = done) works correctly and feels fast.
- **Crop drag creation** — Forward, reverse, bounds clamping, too-small rejection, and high-DPI all pass.
- **Clipboard output** — Basic bitmap output works; content verified by pasting into Paint.
- **Escape routing** — Works across different focus states, idempotent, no crashes.
- **Hit testing** — Crop canvas receives input correctly over the SwapChainPanel.
- **No extra chrome** — The overlay remains focused and minimal, matching the MVP intent.

## Challenges

- **Review findings escalated** — Stories 3.1-3.4 had 13 findings total; Story 3.5 had 14 (7 deferred); Story 3.6 had 11 (7 deferred). Later stories accumulated complexity faster than earlier ones.
- **Story 3.3 adjustment features are dead code** — Release-to-capture auto-confirms on pointer release, so adjustment handles can never be used in the current flow. The entire Adjusting state, handle hit-testing, and replacement gesture logic is unreachable.
- **Three product UX deviations discovered** — No visible Cancel button, no completion feedback, and invalid crop closes overlay instead of staying active. These were not caught during development.
- **Windows manual validation gap persists** — All 6 stories are Windows CI-pass only. Real HDR/SDR, multi-monitor, resource release, and stale callback behavior still need log-based verification.

## Key Learnings

1. **Release-to-capture made adjustment features dead code** — The MVP interaction model (drag + release = done) is correct, but it means Story 3.3's adjustment work cannot be triggered. Future consideration: adjustment may need a different entry mode (e.g., click on existing crop to enter adjustment).
2. **UX deviations need continuous validation against design specs** — The three deviations (no Cancel button, no feedback, invalid crop behavior) were discoverable from the UX spec but were not caught during implementation or code review.
3. **Diagnostic observability is a prerequisite for lifecycle trust** — Users cannot confirm resource release, stale callback rejection, or repeated capture stability without structured logging. UI appearance alone is insufficient.
4. **Deferred review findings accumulate** — Stories 3.5 and 3.6 each had 7 deferred items. This debt should be tracked explicitly.
