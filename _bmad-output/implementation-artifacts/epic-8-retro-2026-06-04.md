# Epic 8 Retrospective: HDR Trust, Recovery, and Release Validation

## Epic Review

Epic 8 was a trust-hardening and release-validation gate. It completed the evidence-backed HDR state model, actionable HDR alerts, structured diagnostics, validation-level records for all MVP capabilities, and the release validation matrix. The epic established Lumiere's release-readiness documentation and confirmed the product can make honest claims about HDR fidelity.

Completed stories:

- 8.1 Complete Evidence-Based HDR State Mapping
- 8.2 Implement Actionable HDR Alerts
- 8.3 Strengthen Structured Diagnostics and Failure Mapping
- 8.4 Record Validation Level for Every MVP Capability
- 8.5 Run MVP Release Validation Matrix

## What Went Well

- **Option C architecture decision (projection-only output states):** Story 8.1 correctly placed output-complete/output-failed as UI projection concerns, not capture lifecycle states. This preserved the integrity of `CaptureSessionState` and `PreviewReadinessState` and was cleanly reused by Stories 8.2 and 8.3.
- **Progressive story dependencies:** Each story built cleanly on the previous — 8.1 state model → 8.2 alerts → 8.3 diagnostics → 8.4 validation audit → 8.5 release matrix. No rework or backtracking was needed.
- **Diagnostic infrastructure quality:** `DiagnosticRecord`, `DiagnosticContext`, and `SessionDiagnosticScope` provide structured, privacy-safe diagnostics across all failure categories (capture, preview, output, interop, tray, hotkey). 34 new tests added.
- **Review process caught real bugs:** Each story review found actionable issues — Chinese overlay messages, InfoBar dismiss override, `OutputResult.Skipped` misclassification, `LogLevel.Critical` downgrade, crop coordinate logging. Review quality improved over the epic.
- **Validation documentation is comprehensive:** The MVP validation registry (31 capability entries) and release validation matrix (43 manual scenarios, 21 classified gaps) provide traceable release-readiness artifacts.
- **Test growth:** 274 → 358 tests across the epic (+84), covering HDR state mapping, alert projection, diagnostic records, privacy validation, and session scoping.

## Challenges

- **All stories Windows CI-pass only:** No Windows manual validation was performed during Epic 8 implementation. All 43 manual scenarios in the release matrix were catalogued as `not-run`. HDR state display, alert display, and diagnostic log auditing all require real hardware.
- **Technical debt accumulation:** Approximately 20 new defer items were added to deferred-work.md across Epic 8 reviews. While most are style preferences or low-risk issues, the accumulation rate exceeds the cleanup rate. 2 pre-existing test failures (`DefaultSettingsProviderTests`) remain unresolved.
- **Documentation-heavy stories have different risk profiles:** Story 8.4 modified 28 files but only added validation level annotations. Story 8.5 produced documentation only. These stories need different review criteria than code stories.
- **HDR state label overlap persists:** Degraded preview shares a label with Enable HDR; Unsupported capture shares a label with HDR unavailable. The implementation achieves 7 distinguishable states vs. the spec's 8-state requirement.

## Key Learnings

- **Projection layer is the correct extension point.** Output states, alerts, and diagnostics are UI projection concerns, not core capture lifecycle. The pattern established in 8.1 was cleanly reused by 8.2 and 8.3. Future features should follow this pattern.
- **Review finding density increases with codebase complexity.** Each story surfaced 5-12 review issues. Part of this is pre-existing code being exposed by new diagnostic coverage. Review standards should scale with codebase complexity.
- **Validation gaps do not close automatically.** The 5 hardware validation gaps from Epic 4 (April) persisted through Epic 8 (June) without being validated. Without a dedicated Windows hardware testing plan, these gaps will remain indefinitely.
- **Deferred debt compounds silently.** Each story's review adds 3-8 defer items. Over 5 stories, this creates 20+ accumulated items. Periodic debt triage is needed to prevent the backlog from becoming unmanageable.
