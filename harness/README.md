# Harness

`harness/` is no longer the project documentation entrypoint. Current product, engineering, validation, and decision docs live under `docs/`.

Use:

- `docs/product/mvp.md`
- `docs/product/roadmap.md`
- `docs/engineering/architecture.md`
- `docs/engineering/workflows.md`
- `docs/validation/mvp-checklist.md`
- `docs/validation/hdr-notes.md`

Project-specific reusable skills may remain under `harness/skills/` when they are still useful, but planning and validation truth should be kept in `docs/`.
